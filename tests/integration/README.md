# 導入・同期の手動統合シナリオ

このシナリオは、AIエージェントがプロンプトに従う運用上の性質を確認します。モデルの出力は非決定的なため通常のユニットテストやCIでは実行せず、エージェントを使った導入・同期を変更したときに、使い捨てのローカルリポジトリで実施します。

## 準備

1. 一時ディレクトリに資料集の作業コピーと対象プロジェクトを用意します。対象プロジェクトには [`fixtures/existing-project/`](fixtures/existing-project/) をコピーし、ローカルGitリポジトリとして初期化します。
2. 資料集の作業コピーで初期コミットSHAを記録します。
3. 対象リポジトリの初期状態を確認し、既存の指示ファイルと課題IDを記録します。

## シナリオA：指示ファイルのないプロジェクトへの初回導入

空の対象リポジトリで [`adopt-guidance.md`](../../prompts/adopt-guidance.md) を実行します。

- 必要な共通資料だけが選ばれ、対象外の資料には理由が記録される。
- `AGENTS.md` と `REVIEWS.md` がない場合、[`create-reviews-md.md`](../../prompts/create-reviews-md.md) を先に、次に [`create-agents-md.md`](../../prompts/create-agents-md.md) を使って整備される。
- `AGENTS.md` はレビュー開始前に `REVIEWS.md` を読むよう指示する。
- 資料ごとの完全な比較基準SHAと、`適用済み`・`部分適用`・`保留`・`対象外` の状態が実際の反映内容に合う。
- 導入先のリンクが解決し、資料集の作業コピーは変更されない。

## シナリオB：既存ルールを保護した部分適用と同期

1. fixtureを対象に初回導入を行い、既存の `AGENTS.md`、`REVIEWS.md`、`ISS-0042` を保持する。
2. 少なくとも1資料を一部だけ適用し、未適用部分と理由を適用メモに記録する。
3. 資料集側のその資料を変更してコミットし、変更の一部と対象プロジェクトの既存ルールが競合する状態を作る。
4. [`sync-guidance.md`](../../prompts/sync-guidance.md) を実行する。安全な差分は反映し、競合は保留として残す。
5. 同期をもう一度実行し、反映済み差分が重複せず、保留差分・理由が再提示されることを確認する。

## 結果の記録

確認したプロンプト、資料集の比較元・比較先SHA、対象fixtureの状態、反映・保留の結果、リンク検査、未確認事項を作業報告に記録します。実際にエージェント実行をしていない場合は、シナリオを未実施と明記します。
