# UI/UX設計クイックチェック

設計レビューや実装前後の確認に使う短いチェックリストです。適用条件と具体例は[UI/UX設計ガイド](ui-ux-guide.md)の該当節を確認してください。該当しない項目は理由を添えて除外します。

## 目的と情報構造

- [ ] 対象ユーザー、主要タスク、成功条件が明確。
- [ ] 画面・機能名がユーザーの目的や既存の用語と合っている。
- [ ] 優先度の高いタスクが見つけやすく、情報の階層とナビゲーションが一貫。
- [ ] 初回利用と継続利用の双方で、必要な情報を認識できる。

## 操作と状態

- [ ] Idle、Loading、Empty、Success、Error、Disabledなど必要な状態を定義。
- [ ] 操作後に結果・進捗・失敗理由が分かり、再試行・取消・復旧の方法がある。
- [ ] 破壊的操作を誤りにくくし、可能な場合は取り消しや復元を用意。
- [ ] 重複送信、通信失敗、保存失敗など現実の失敗条件を扱う。

## アクセシビリティと入力

- [ ] キーボードだけで主要タスクを完了でき、フォーカス位置が見える。
- [ ] テキスト、コントラスト、拡大表示、色以外の状態表現を確認。
- [ ] 支援技術にラベル・役割・状態・エラーを伝える。
- [ ] タッチ・マウス・キーボードの操作対象と対象サイズを確認。
- [ ] Reduced MotionやOSの表示設定を考慮。

## 表示と環境

- [ ] 狭い幅、拡大率、長い文字列、複数言語で崩れない。
- [ ] 色、文字、余白、状態表示が画面間で一貫。
- [ ] Web・デスクトップそれぞれの標準操作やOS連携を確認。
- [ ] 待ち時間を測り、進捗表示や応答性の目標を定義。

## 安全性と評価

- [ ] データ損失や誤操作の可能性と、確認・復旧手段を評価。
- [ ] 個人情報、権限、AI生成内容の不確実性を利用者へ適切に示す。
- [ ] 代表的な利用者とタスクで、実際の操作を検証。
- [ ] 使用した検証方法、未確認の環境、残る問題を記録。
