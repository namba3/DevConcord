# メイン課題表

連合課題表構成のプロジェクト索引です。小規模プロジェクトは[単一課題表テンプレート](issue-register.md)を利用し、複数ファイルへの分割を強制しません。詳しい規約は[課題管理・完成度評価規約](../issue-tracking.md)を参照してください。

## プロジェクト完成度評価

[単一課題表テンプレート](issue-register.md)から既存10軸完成度評価とSDSの各節だけを移すか、プロジェクトの既存評価を維持します。評価軸・重みは変更しません。

## 共通ISS採番

- **次の未割当番号:** （全サブ課題表を確認して記録）
- **採番確認日:** YYYY-MM-DD
- **確認根拠:** この索引とリンク先サブ課題表を照合

採番状態はこのメイン課題表だけで管理します。次番号を使う前に既存の全課題表で重複を確認し、課題を正本へ記録した後に次番号を進めます。番号は再利用せず、競合・過去状態の不明があれば採番を止めて確認してください。

## サブ課題表

ここには各サブ課題表の目的とリンクだけを記載します。個々の課題状態・詳細・履歴・検証証拠を複製しません。

| 領域・目的 | 課題表 |

## 重要課題

必要な場合に限り、完成度評価やプロジェクト全体への影響を阻害する課題へのリンクを置きます。状態や詳細の複製はせず、リンク先の課題表を正本とします。

- （必要な場合は `ISS-####` と正本へのリンク）

## タグ定義（任意）

単一課題表構成では同じ課題表に定義を置きます。定義表はプロジェクト内で一つだけとし、タグが不要なら節ごと省略できます。以下は推奨値であり、固定リストではありません。

| タグ | 意味 |
|---|---|
| ARCH | アーキテクチャ・設計 |
| CORE | コア機能・内部処理 |
| QA | テスト・品質保証 |
| OPS | 開発環境・ビルド・CI/CD・運用 |
| DOC | ドキュメント |
| SEC | セキュリティ |
| PERF | パフォーマンス |
| UX | UI/UX |
| REL | 信頼性・堅牢性 |

短い大文字英数字を使い、同義タグを増やしません。定義変更時は使用中の課題への影響を確認します。
