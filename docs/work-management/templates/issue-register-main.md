# メイン課題表

連合課題表構成のプロジェクト索引です。小規模プロジェクトは[単一課題表テンプレート](issue-register.md)を利用し、複数ファイルへの分割を強制しません。詳しい規約は[課題管理・完成度評価規約](../issue-tracking.md)を参照してください。

## プロジェクト完成度評価

- **総合完成度:** 未確定
- **暫定総合完成度:** 未算出
- **評価済みカバレッジ:** 0%
- **評価日:** YYYY-MM-DD
- **評価対象:** リポジトリ／ブランチ／コミット
- **評価の確度:** 未評価（高／中／低）
- **リリース判定:** 未判定（可／条件付き／不可／未判定）

「未評価」は評価対象だが根拠不足、「N/A」は理由を記録したうえで対象外とする軸を表す。未評価軸が残る間、正式な総合完成度は未確定とし、暫定値を表示する場合は評価済みカバレッジを併記する。算出方法は上記の課題管理規約を参照する。

## 共通ISS採番

Issue IDはプロジェクト共通の不変な `ISS-####` 連番です。4桁以上を使い、既存IDを変更・再利用しません。

- **次の未割当番号:** `ISS-0001`（例示値。全索引先を確認し、実際の次番号へ置き換える）
- **採番確認日:** YYYY-MM-DD
- **確認根拠:** この索引とリンク先サブ課題表を照合

採番状態はこのメイン課題表だけで管理します。次番号を使う前に既存の全課題表で重複を確認し、課題を正本へ記録した後に次番号を進めます。番号は再利用せず、競合・過去状態の不明があれば採番を止めて確認してください。

## サブ課題表

各サブ課題表の目的と相対リンクだけを記録し、個々の課題状態・詳細・履歴・検証証拠を複製しません。以下は配置例です。実際に利用する場合は示したパスにサブ課題表を作成し、実際の領域名に置き換えてください。

| 領域・目的 | 課題表 |
|---|---|
| Architecture | [architecture.md](issues/architecture.md) |
| Quality | [quality.md](issues/quality.md) |

上記のリンク先はこのテンプレートに含まれる例示用の空スケルトンです。導入時は必要なファイルだけを実プロジェクトの管理対象ディレクトリへ配置・編集し、不要な例を索引から削除してください。

## 重要課題

必要な場合に限り、完成度評価やプロジェクト全体への影響を阻害する課題へのリンクを置きます。状態や詳細の複製はせず、リンク先の課題表を正本とします。リンク先はサブ課題表とISS IDの正本に一致させてください。個別課題の見出しがない場合はファイル単位リンクを使えます。見出しアンカーを指定する場合は、その見出しを実在させ、参照するISSと整合させます。

```markdown
- [ISS-0125](issues/architecture.md)
- [ISS-0125](issues/architecture.md#iss-0125)
```

上記は記法例であり、コピー前に実在するパス・ID・見出しへ置き換えてください。

## タグ定義（任意）

単一課題表構成では同じ課題表に定義を置きます。定義表はプロジェクト内で一つだけとし、タグが不要なら節ごと省略できます。以下は推奨値であり、固定リストではありません。

| タグ | 意味 |
|---|---|
| ARCH | アーキテクチャ・設計 |
| CORE | コア機能・内部処理 |
| QA | テスト・品質保証 |
| OPS | 開発環境・ビルド・CI/CD・運用 |
| DOC | ドキュメント |
| SEC | セキュリティ |
| PERF | パフォーマンス |
| UX | UI/UX |
| REL | 信頼性・堅牢性 |
| IDEA | アイデア |
| REQ | 利用者要望・要求候補（タグ。`REQ-####`要求IDとは別） |
| ENH | 既存機能の改善提案 |

短い大文字英数字を使い、同義タグを増やしません。定義変更時は使用中の課題への影響を確認します。
